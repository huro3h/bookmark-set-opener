# Bookmarks Launcher 開発メモ

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `bookmarks.js` | ブックマークの木を平らにする `readTree()`、フォルダ直下の URL、タブを開く `openUrls()` |
| `sets.js` | セットとブックマークの照合、エクスポート/インポート |
| `settings.js` | `chrome.storage.local` の読み書きとスキーマ |
| `background.js` | タブを開く処理の実行役(ポップアップからのメッセージとショートカットキーの両方)。`"type": "module"` |
| `popup.*` | セットの一覧と確認だけ(フォルダ・検索欄は出さない)。左上に控えめな拡張名と `v<manifest の version>`、右上の歯車で設定画面 |
| `options.*` | セットの一覧・編集・エクスポート/インポート、スロットの割り当て |
| `icons/icon.svg` | アイコンの原本(ブックマークのリボンを2枚重ねた形)。ポップアップのセットの行にも同じ形を使っている |

共有モジュールはすべて ES module で、3画面から `import` する。

## ストレージ(すべて `chrome.storage.local`)

```
sets:     [{ id: uuid, name, background, items: [{ url, title }] }]   表示順。エクスポートの対象
bindings: { [url]: bookmarkId }                           この環境だけの対応表
slots:    [{ type: "folder" | "set", id } | null] × 5
```

## 中心にある設計判断

### セットの項目は URL とタイトルだけを持ち、ID は別の対応表に置く

ブックマークの `id` はプロフィールごとに作成順に振られる番号の文字列。編集・移動・再起動では変わらないが、
**端末・ブラウザ(Stable と Beta など)・プロフィールが違えば、同じ Google アカウントでも別の番号になる**
(同期で届いたブックマークにも受け取った側が番号を振る)。

そのため ID をセットの中に入れてエクスポートすると、別の環境では**同じ番号が別のブックマークを指して**
黙って違うページを開く。そこで:

- 持ち運ぶデータ(`sets`)は `{ url, title }` だけ
- 「この URL はこの環境では ID 何番か」を `bindings` に別に持ち、エクスポートしない

照合(`sets.js` の `resolve`)は各項目について:

1. `bindings[url]` の ID のブックマークがあればそれ。URL やタイトルが変わっていたら**項目のほうを書き換える**
   (ブックマークの編集にセットが追従する)
2. なければ同じ URL のブックマークを探し、見つかれば `bindings` に記録(インポート直後・登録し直したとき)
3. どちらもなければ `bookmarkId: null`。**開くときは保存してある URL をそのまま開く**(項目はセットから消さない)

`loadSets()` が照合し、変化があればその場で保存する。ポップアップ・設定画面を開いたときと、
セットを開くときに毎回呼ばれる。

ハマりどころ: URL が変わったとき古い URL の対応を `delete` すると、同じ URL を持つ**別のセット**の
項目が照合で見つからなくなる。古い対応は残しておき、どのセットからも使われなくなった時点で
`saveSets()` がまとめて捨てる。

同じ URL のブックマークが複数あれば、木の先頭のものに結び付く。

### エクスポート形式

```json
{ "format": "bookmarks-launcher", "version": 1, "exportedAt": "...",
  "sets": [{ "id": "<uuid>", "name": "...", "items": [{ "url": "...", "title": "..." }] }] }
```

セットの並び(配列の順 = ポップアップの表示順)とセットの中の並び(`items` の順 = 開く順)は配列の順でそのまま入る。
インポートは「ファイルにないセット(今の並び)」+「取り込んだセット(ファイルの並び)」に並べ直し、同じ `id` は置き換える
(同じファイルを読み直しても重複しない。全部を書き出したファイルを戻せば並びも書き出したときに戻る)。
以前は同じ `id` をその場で置き換えていたので、並べ替えた後にバックアップを戻してもセットの並びが戻らなかった。
並びの保存と復元は scratchpad の別スクリプト(セット3つ・木と違う中の並び)で、空の環境・並べ替え後・ファイルにないセットがある環境の3通りを確かめた。
スロットはファイルに含めない(フォルダの ID は環境ごとに違うため、セットだけ持ち運んでも意味が通らない)。
`chrome.storage.sync` での自動同期は採らなかった。容量が合計約 100KB と小さいのと、
パッケージ化されていない拡張は環境ごとに拡張の ID が変わって同期されない(manifest に `key` が要る)ため。

### タブを開くのは service worker(ポップアップではない)

`tabs.create({ active: true })` でタブが選択された瞬間にポップアップは閉じ、その時点でポップアップの JS は止まる。
ポップアップでループを回すと最初の1枚だけ開いて終わる。そこでポップアップは
`sendMessage({ type: "open", target: { type, id } })` を送るだけにして、`background.js` が最後まで開く。

開く先は `windows.getLastFocused({ windowTypes: ["normal"] })` の `windowId` を明示する
(service worker には「今のウィンドウ」がない)。通常のウィンドウがなければ `windows.create({ url: urls })`。
1つの URL が開けなくても残りは開くよう、`tabs.create` は1件ずつ try で囲んでいる。

### ポップアップはセットだけ

当初はポップアップにフォルダ一覧(階層表示)とセット名の検索欄もあったが、ユーザーの判断でどちらも削除した。
右上の歯車は smart-keysmith と同じ lucide の `settings` アイコン・同じ配置(左上に控えめな拡張名、右上に 32px のアイコンボタン)。
行の右には、そのセットを割り当てたスロットに**実際に設定されているキー**を `<kbd>` で出す(`commands.getAll()` の `shortcut`)。
キー未設定のスロットなら何も出さない(当初はスロット番号を丸数字で出していたが、意味が分かりにくいとのことで変えた)。
フォルダを開く機能はショートカットキーのスロットにだけ残っている(`background.js` の `folderUrls()`)。

フォルダを開くときは**直下だけ**。再帰的に開くと深い階層で想定外の数のタブが開くので採らなかった。
`readTree()` は開けるブックマークを子孫に1つも持たないフォルダを除く(スロットの選択肢とセット編集のバーで使う)。
`javascript:` のブックマークレットはどこでも除く。

### バックグラウンドで開く(セットごと)

`set.background === true` なら `openUrls(urls, { background: true })` で全タブを `active: false` で作る。
既定(false)は最初のタブだけ `active: true`。
切り替えは設定画面の**セット一覧の各行**のチェックボックスで、変えた時点で保存する(当初は編集画面に置いたが、
ユーザーの要望で一覧へ移した)。編集画面で保存するときは、一覧で設定済みの値をそのまま引き継ぐ。通常のウィンドウが1つもなくて `windows.create` に回る場合は無視する。
フォルダのスロットは常に既定どおり。

### セットの並び順

開く順は `set.items` の保存順で、編集画面の「n 件を選択中」の一覧で**ドラッグして**決める(以前はブックマークの木の並び順に
固定していたが、並べ替えたいという要望で変えた)。編集中は `editing.order`(キーはブックマークの ID か `missing:<添字>`)が並びを持ち、
`changeSelection()` の中の `normalizeOrder()` が選択とそろえる — 外れたものを抜き、新しく選ばれたものを**末尾**に足す
(「すべて選択」でまとめて足すときは木の並び順、そのあとにブックマークにない項目)。既存のセットを開いたときは保存順のまま。
並べ替えも `changeSelection` を通るので Undo できる(写しに `order` も入れ、同じかどうかは `order` の一致で見る)。

セット自体の順(ポップアップの表示順)は設定画面のセット一覧でドラッグして変える(以前は ▲▼)。

### ドラッグでの並べ替え(`drag.js`)

smart-keysmith の方式をそのまま共通モジュールにした。`handle()` が `⠿` のハンドル(これだけ `draggable`)を作り、
`enableDragReorder(listEl, onReorder)` がリスト側に HTML5 の drag イベントを張る(行を描き直しても生き残る)。
ドラッグ中は行そのものを DOM の中で動かし(カーソルより下でいちばん近い行の前へ)、`dragend` で並びが変わっていれば
`onReorder(data-key の配列)` を呼ぶ。行の中のボタン(× や編集)はハンドル以外なので普段どおり押せる。
smart-keysmith にあるタッチ用(Pointer Events)の処理は、拡張の設定画面はマウスで使うので入れていない。


### セット編集画面(ブックマークバー)

ブラウザ上部のブックマークバーを再現した表示だけで選ぶ。経緯: 最初はチェックボックス付きのツリー → 数が多いと探しにくいので
タイル + パンくずの「バー風」をタブで追加 →「バーそのものが良い」と言われて再現に作り直し → ツリー(とタブ・検索欄・
見出し「ブックマーク」・説明文)は使わないとのことで削除した。
開く時に `indexHierarchy()` で、`readTree()` の平らな配列から「フォルダ → 子孫のブックマーク ID」
「フォルダ → 直下の要素(null は最上位)」の索引を作る。

**チェックボックスは使わない。** チップ・メニュー項目をすべて `<button>` にし、押すと選択/解除、
選択中は `.selected`(青い枠 + `--accent-tint` の背景、`aria-pressed`)で示す。
枠は `border` + `inset box-shadow` で太らせ、選択の有無で大きさが変わらないようにしている。
選択を変えるたびに描き直すとメニューが閉じてしまうので、`syncSelection()` が `#editor [data-kind]` のクラスだけを書き換える。

- **バー**: ブックマーク バー(id `"1"`)の直下を横に並べ、ほかの最上位フォルダ(その他のブックマーク等)は右端。
  - 表示はブラウザと同じくファビコン + サイト名だけ(タイトルが空ならファビコンだけ)。URL は `title` のツールチップ
  - フォルダ(`data-kind="folder-menu"`)は押すとドロップダウン(`.bm-menu`、`position: fixed`、`#menus` に入れる)。
    メニュー内のサブフォルダは**マウスを乗せると**右にサブメニュー、ブックマークに乗せると深いメニューを閉じる。
    メニューを開いている間はバーの別フォルダに乗せるだけで切り替わる(どれもブラウザの挙動に合わせた)
  - バーのフォルダは押すたびに開閉するが、**乗せただけで開いた直後(600ms 以内)のクリックでは閉じない**。
    ほかのメニューを開いた状態で別のフォルダへ移って押すと、hover で開いた直後のクリックで閉じてしまっていた
  - ブラウザと違い、メニューのブックマークを押しても**メニューは閉じない**(続けて選べるように)
  - メニューの末尾に「このフォルダをすべて選択 (n)」(`data-kind="select-all"`、子孫が対象。全部選択済みなら「解除」)
  - 中に選択を含むフォルダは `.has-selected`(青い枠とアイコン)
  - **縦は常にバーより下に出す**(ブラウザと同じ)。最初のメニューはボタンではなくバー(`.bmbar`)の下端から出し、
    `max-height` を画面下端までにして中をスクロールさせる。サブメニューは下に収まらなければ持ち上げるが、最初のメニューの
    上端より上には出さない。以前は画面に収めるため上にずらしていて、バーに重なってほかのフォルダが押せなくなっていた
  - 閉じるのはメニュー外の mousedown / Esc / スクロール / リサイズ(fixed なのでスクロールで位置がずれるため)。
    Undo ボタンを押すのも「外側」なのでメニューは閉じる(キーボードの Undo なら開いたまま)
  - **入りきらない分は本物と同じく「»」(`.bmbar-more`)にしまう**(2.1.0 までは `flex-wrap` で折り返して全部出していたが、
    実物と同じ動きにという要望で変えた)。`layoutBar()` が全部出してから測り、はみ出していれば「»」を出して
    (その分バーが狭くなる)から、右端を越えたチップ**以降を全部** `hidden` にする(途中だけ飛ばして詰めない。ブラウザと同じ)。
    幅は `ResizeObserver` でバーを見て測り直す(ウィンドウのリサイズだけでなく、スクロールバーの出入りでも変わるため)。
  - 「»」のメニューは `openMenu(OVERFLOW, ...)` で、フォルダのメニューと同じ部品・同じ開閉(押すたびに開閉、メニューを開いている間は
    乗せるだけで切り替え)。中身は `overflowEntries`(しまったもの、バーの並び順)。フォルダではないので「すべて選択」は付けない。
    しまったものの中に選択があれば「»」に `.has-selected` の印。しまう中身が変わったら開いている「»」のメニューは閉じる
  - 編集画面(`#editor`)はバーのため**ブラウザの横幅いっぱい**(`max-width: none`)
- **見出しの行**(`.editor-head`): 「新しいセット」・名前の欄・(右端に `.editor-actions`)↶ ↷ キャンセル 保存 を1行に並べる。
  部品の高さは 34px にそろえる。以前は画面下に sticky のフッター(件数・Undo/Redo・キャンセル・保存)があったが、
  件数が一覧の見出しと重複するという要望で、ボタンをこの行へ移してフッターごと削除した
- **選択中のブックマーク**(`#selectedSection`): バーの下に、保存するとセットに入る項目を開く順で並べる
  (ファビコン・タイトル・URL・× で外す)。見出しは「n 件を選択中」(`#selectedHeading`)。`updateEditorState()` のたびに描き直す。
  件数だけでは何を選んだか分からないという要望で足した。バーの**上**に置くと、選ぶたびにバーが下へずれて
  開いているメニュー(fixed)と食い違うので下に置いた。
  この環境のブックマークに見つからない項目(`editing.missing`)もここに「ブックマークにない」の印付きで出し、× で外す
  (以前は別の欄にトグルで出していたが、ツリーの部品を使っていたのでツリー削除時に一覧へ統合した。外し間違いは Undo で戻す)
- 行・メニュー項目の中身は ファビコン → タイトル(一覧では → URL)。ファビコンは `favicon` 権限で
  `chrome.runtime.getURL("/_favicon/?pageUrl=<URL>&size=32")` を 16px で表示する(ブックマークバーと同じブラウザのキャッシュ。
  外部へは取りに行かない)。一度も開いていないサイトは既定の地球儀アイコンになる。Brave でも動く

### Undo / Redo(セット編集画面)

選択を変える操作(チップ・メニュー項目・「すべて選択/解除」・一覧の ×)はすべて `changeSelection(apply)` を通し、
操作前の選択の写し(`selected` の Set と `missing` の checked 配列)を `editing.undo` に積む。中身が変わらなかった操作は積まない。
新しい操作で `redo` は空にする。上限 200。編集画面を開くたびに履歴は空から始まる。

- 見出しの行の右端の ↶ ↷ ボタン(`#undo` / `#redo`、履歴がなければ disabled)。lucide の undo-2 / redo-2
- キーボードは `⌘Z` / `⇧⌘Z` と `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`。**入力欄(名前)にフォーカスがあるときは横取りしない**
  (文字入力の Undo を優先)
- 名前の変更は履歴に入れない(入力欄そのものの Undo に任せる)
- 誤って「このフォルダをすべて選択」を押したとき、× を1つずつ押すのが面倒という要望で入れた

### ショートカットキー

- コマンド名は `01_open_slot` 〜 `05_open_slot`。`chrome://extensions/shortcuts` は manifest のキー名順で並ぶので
  数字を頭に付けている。`parseInt(command)` でスロット番号も取れる。`suggested_key` は付けない(付けられるのは4つまでだが、付けなければ数の制限はない)。2.3.0 で3つから5つに増やした(使わない枠が `chrome://extensions/shortcuts` に並ぶのを嫌って、多めには取らない)。
  コマンド名の組み立て(`0${i + 1}_open_slot`)は1桁前提なので、10個以上にするなら直す
- 失敗(未割り当て・削除済み・空)は画面に出ないので、アイコンに赤い「!」バッジを4秒出し、理由を `setTitle` に入れる
- セットを削除すると、それを割り当てていたスロットは空にする。フォルダの削除は検知していない(設定画面に「見つかりません」と出る)

### 設定画面のボタン

セット一覧の編集・削除は simple_memo と同じ形のアイコンボタン(26px・枠付き・ホバーで塗りつぶし、lucide 系の
鉛筆付きの四角とゴミ箱)。色はこの拡張の `--accent`(編集)と `--error`(削除)。
編集の左に複製のボタンがある。アイコンは smart-keysmith の複製と同じ lucide の `copy-plus`(重なった四角だけの `copy` だと
クリップボードへのコピーに見えるため「+」付き)で、色は smart-keysmith のアイコンと同じ青緑 `--dup`(`#0FA3B1`、
ユーザーの指定。暗い画面でも同じ色で読める)。

複製は元のすぐ下に「〜 のコピー」として入れ、トースト「「〜」を複製しました」を出す(元に戻すボタンは付けない。不要なら削除すればよい)。
中身・開く順・`background` は引き継ぎ、**スロットの割り当ては引き継がない**(同じキーで2つを開くことはできないので)。
項目は照合済みの `bookmarkId` ごとコピーするので、複製もはじめから同じブックマークに結び付いている。

### 一覧での名前の変更

セット一覧の名前(`.set-name`)は `<button>` で、押すと `renameInPlace()` がその場で入力欄(`.set-name-input`)に差し替える。
Enter・blur で保存、Esc で取り消し。空白だけ・変わっていなければ元の名前に戻すだけ。変換中(`isComposing`)の Enter / Esc では終わらない。

- 終わったら**その行だけ**ボタンに戻し、名前が出るスロットの選択肢だけ `renderSlots()` で描き直す。一覧ごと `renderMain()` すると、
  編集中に別の行の名前を押したとき、blur の描き直しで押した先が消えてクリックが空振りする
- Enter の keydown は `preventDefault()` する。しないと、フォーカスを戻した名前のボタンがその Enter で押されて、また入力欄が開く
- ボタンと入力欄は余白(`1px 6px`)・枠(1px)・`line-height` をそろえ、切り替えても行の高さと文字の位置が動かない。
  件数の行は名前の文字にそろえて 7px 字下げ。`.input` のほうが後ろに書いてあるので、入力欄側は `.input.set-name-input` で指定している
- 名前を押せるようにしたので、誤ってハンドルを掴まないよう `.set-text` に `margin-left: 4px`(ハンドルとの間は計 12px)。ユーザーの要望

### 20 個以上を開くときは二度押し、セットの削除はトーストで元に戻す

20 個以上を開くとき(ポップアップ)は、1回目で表示を変え 3 秒以内のもう一度で実行する。
`confirm()` はポップアップを固めるうえ自動テストもしにくいので使わない。ショートカットキーからは確認なしで開く。

セットの削除(設定画面)は**1クリックで消し**、画面下に「「〜」を削除しました [元に戻す]」のトーストを 6 秒出す
(以前はゴミ箱の二度押しだったが、要望でこの形にした)。トーストの見た目は smart-reload と同じ(暗い角丸、下中央)に
アクションのボタンを足したもの。マウスを乗せている間は消えない。新しいトーストは前のものを置き換える(前の「元に戻す」は効かなくなる)。
元に戻すと、元の位置に差し戻し、削除のときに空にしたスロットも割り当て直す(その間にほかのものを割り当てたスロットはそのまま)。
セットの中身は照合済み(`bookmarkId` 付き)のまま持っているので、`storeSets` で対応表もそのまま戻る。

## テスト手順(Playwright + Brave Nightly)

使い捨てのスクリプトは scratchpad に置く(このリポジトリには置かない)。

1. リポジトリを `--load-extension` で読み込み、`ctx.serviceWorkers()` の URL から拡張の ID を取る
2. service worker で `chrome.bookmarks.create` を使ってテスト用のブックマークを作る(ブックマーク バーは `"1"`、
   その他のブックマークは `"2"`)。URL はテスト内で立てた `http://localhost:<port>/...`。名前は架空のもの
3. `popup.html` / `options.html` を普通のタブで開いて操作する。ポップアップの行は `data-id="<セットの id>"` で特定できる
   - **行を押すと `window.close()` でそのタブ自体が閉じる。** その後の待ちに `page.waitForTimeout` を使うと
     「Target page has been closed」で落ちるので、service worker 側の `setTimeout` で待つ
   - 開いたタブの URL は `ctx.pages()` で数える。`tabs` 権限がないので service worker の `tabs.query` では `url` が取れない
   - 選択中のタブの判定に `document.visibilityState` は使えない(Playwright 下では全タブ visible)。
     拡張ページから `tabs.query({ active: true, lastFocusedWindow: true })` の ID と `tabs.getCurrent()` の ID を比べる
     (ID は `tabs` 権限なしでも取れる)。ポップアップは自分のタブを閉じた拍子に別のタブが選択されるので、
     バックグラウンドの確認は設定画面から `sendMessage({ type: "open", ... })` を送って行う
   - **ショートカットキーはコードから設定できない**(`chrome.commands.update` は Firefox のみ)。ポップアップのキー表示は
     `page.addInitScript` で `chrome.commands.getAll` を差し替えてから `popup.html` を開いて確かめる
   - ファビコンの確認は、テストサーバーの一部のページに `<link rel="icon">`(赤い丸の data URL)を付けて一度開いてキャッシュさせ、
     編集画面の `<img>` を canvas に描いて中央の画素が赤いか(付けていないページは赤くないか)で見る
   - 編集画面のバーは `.bmbar .bm-chip`、メニューは `#menus .bm-menu:nth-child(階層) .menu-item` で特定する。
     サブメニューは `hover()` で開く。タイトルで引くときは `:has(.title:text-is("..."))`。選択状態は `.selected` クラスで見る
   - ドラッグは `page.dragAndDrop('<行> .drag-handle', '<行>', { targetPosition: { x: 40, y: 3 } })` で HTML5 の drag イベントが出る。
     落とす先の行の上端あたりを指すと、その行の前に入る
   - Undo ボタンを `click()` するとメニューは閉じる(外側を押したことになる)。メニューを開いたまま戻すなら
     `keyboard.press('Control+z')`。名前の欄で Ctrl+Z を押すと文字入力の Undo が効いて名前が消えるので、入れ直してから保存する
   - エクスポートは `page.waitForEvent('download')`、インポートは `setInputFiles('#importFile', path)`
