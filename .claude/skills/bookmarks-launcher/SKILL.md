# Bookmarks Launcher 開発メモ

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `bookmarks.js` | ブックマークの木を平らにする `readTree()`、フォルダ直下の URL、タブを開く `openUrls()` |
| `sets.js` | セットとブックマークの照合、エクスポート/インポート |
| `settings.js` | `chrome.storage.local` の読み書きとスキーマ |
| `background.js` | タブを開く処理の実行役(ポップアップからのメッセージとショートカットキーの両方)。`"type": "module"` |
| `popup.*` | セットの一覧と確認だけ(フォルダ・検索欄は出さない)。右上の歯車で設定画面 |
| `options.*` | セットの一覧・編集・エクスポート/インポート、スロットの割り当て |
| `icons/icon.svg` | アイコンの原本(ブックマークのリボンを2枚重ねた形)。ポップアップのセットの行にも同じ形を使っている |

共有モジュールはすべて ES module で、3画面から `import` する。

## ストレージ(すべて `chrome.storage.local`)

```
sets:     [{ id: uuid, name, background, items: [{ url, title }] }]   表示順。エクスポートの対象
bindings: { [url]: bookmarkId }                           この環境だけの対応表
slots:    [{ type: "folder" | "set", id } | null] × 3
```

## 中心にある設計判断

### セットの項目は URL とタイトルだけを持ち、ID は別の対応表に置く

ブックマークの `id` はプロフィールごとに作成順に振られる番号の文字列。編集・移動・再起動では変わらないが、
**端末・ブラウザ(Stable と Beta など)・プロフィールが違えば、同じ Google アカウントでも別の番号になる**
(同期で届いたブックマークにも受け取った側が番号を振る)。

そのため ID をセットの中に入れてエクスポートすると、別の環境では**同じ番号が別のブックマークを指して**
黙って違うページを開く。そこで:

- 持ち運ぶデータ(`sets`)は `{ url, title }` だけ
- 「この URL はこの環境では ID 何番か」を `bindings` に別に持ち、エクスポートしない

照合(`sets.js` の `resolve`)は各項目について:

1. `bindings[url]` の ID のブックマークがあればそれ。URL やタイトルが変わっていたら**項目のほうを書き換える**
   (ブックマークの編集にセットが追従する)
2. なければ同じ URL のブックマークを探し、見つかれば `bindings` に記録(インポート直後・登録し直したとき)
3. どちらもなければ `bookmarkId: null`。**開くときは保存してある URL をそのまま開く**(項目はセットから消さない)

`loadSets()` が照合し、変化があればその場で保存する。ポップアップ・設定画面を開いたときと、
セットを開くときに毎回呼ばれる。

ハマりどころ: URL が変わったとき古い URL の対応を `delete` すると、同じ URL を持つ**別のセット**の
項目が照合で見つからなくなる。古い対応は残しておき、どのセットからも使われなくなった時点で
`saveSets()` がまとめて捨てる。

同じ URL のブックマークが複数あれば、木の先頭のものに結び付く。

### エクスポート形式

```json
{ "format": "bookmarks-launcher", "version": 1, "exportedAt": "...",
  "sets": [{ "id": "<uuid>", "name": "...", "items": [{ "url": "...", "title": "..." }] }] }
```

インポートは同じ `id` のセットを置き換え、ほかは末尾に足す(同じファイルを読み直しても重複しない)。
スロットはファイルに含めない(フォルダの ID は環境ごとに違うため、セットだけ持ち運んでも意味が通らない)。
`chrome.storage.sync` での自動同期は採らなかった。容量が合計約 100KB と小さいのと、
パッケージ化されていない拡張は環境ごとに拡張の ID が変わって同期されない(manifest に `key` が要る)ため。

### タブを開くのは service worker(ポップアップではない)

`tabs.create({ active: true })` でタブが選択された瞬間にポップアップは閉じ、その時点でポップアップの JS は止まる。
ポップアップでループを回すと最初の1枚だけ開いて終わる。そこでポップアップは
`sendMessage({ type: "open", target: { type, id } })` を送るだけにして、`background.js` が最後まで開く。

開く先は `windows.getLastFocused({ windowTypes: ["normal"] })` の `windowId` を明示する
(service worker には「今のウィンドウ」がない)。通常のウィンドウがなければ `windows.create({ url: urls })`。
1つの URL が開けなくても残りは開くよう、`tabs.create` は1件ずつ try で囲んでいる。

### ポップアップはセットだけ

当初はポップアップにフォルダ一覧(階層表示)とセット名の検索欄もあったが、ユーザーの判断でどちらも削除した。
右上の歯車は smart-keysmith と同じ lucide の `settings` アイコン・同じ配置(左上に控えめな拡張名、右上に 32px のアイコンボタン)。
行の右には、そのセットを割り当てたスロットに**実際に設定されているキー**を `<kbd>` で出す(`commands.getAll()` の `shortcut`)。
キー未設定のスロットなら何も出さない(当初はスロット番号を丸数字で出していたが、意味が分かりにくいとのことで変えた)。
フォルダを開く機能はショートカットキーのスロットにだけ残っている(`background.js` の `folderUrls()`)。

フォルダを開くときは**直下だけ**。再帰的に開くと深い階層で想定外の数のタブが開くので採らなかった。
`readTree()` は開けるブックマークを子孫に1つも持たないフォルダを除く(スロットの選択肢とセット編集のツリーで使う)。
`javascript:` のブックマークレットはどこでも除く。

### バックグラウンドで開く(セットごと)

`set.background === true` なら `openUrls(urls, { background: true })` で全タブを `active: false` で作る。
既定(false)は最初のタブだけ `active: true`。
切り替えは設定画面の**セット一覧の各行**のチェックボックスで、変えた時点で保存する(当初は編集画面に置いたが、
ユーザーの要望で一覧へ移した)。編集画面で保存するときは、一覧で設定済みの値をそのまま引き継ぐ。通常のウィンドウが1つもなくて `windows.create` に回る場合は無視する。
フォルダのスロットは常に既定どおり。古いデータやインポートで `background` が無ければ false 扱い。

### セットの並び順

項目は編集画面で保存するとき**ブックマークの木の並び順**にそろえ、「ブックマークにない」項目はその後ろに元の順で置く。
開く順はこの保存順。セット自体の順は設定画面の ▲▼ で変える。

### セット編集画面(ツリー / ブックマークバー)

ブックマーク欄はタブで2つの表示を切り替える。最後に使った表示は `storage.local` の `editorView` に覚える。
数が多いと縦一列のツリーから探すのが大変、という要望でバー表示を足した(ツリーも残している)。
開く時に `indexHierarchy()` で、`readTree()` の平らな配列から次の索引を作る:
「フォルダ → 子孫のブックマーク ID」「要素 → 祖先フォルダ ID」「フォルダ → 直下の要素(null は最上位)」「ID → 要素」。

**チェックボックスは使わない。** 大量に並ぶと分かりにくいという要望で、行・チップ・メニュー項目をすべて `<button>` にし、
押すと選択/解除、選択中は `.selected`(青い枠 + `--accent-tint` の背景、`aria-pressed`)で示す。
枠は `border` + `inset box-shadow` で太らせ、選択の有無で大きさが変わらないようにしている。
選択を変えるたびに描き直すとフォーカスやメニューが飛ぶので、`syncSelection()` が `#editor [data-kind]` のクラスだけを書き換える。

- **ツリー**: `depth × 20px` で字下げ。折りたたみは付けない(ユーザーの判断で不要とした)。
  フォルダ行を押すと子孫(サブフォルダを含む)を `toggleAll` — 全部選択済みなら全解除、そうでなければ全選択。
  一部だけ選択中のフォルダは `.partial`(点線の枠)。タリーは `選択数 / 総数`。
  絞り込みはツリーだけ。当たったブックマークとその祖先フォルダだけを出し、フォルダ行は**当たったものだけ**を対象にする
- **ブックマークバー**: ブラウザ上部のバーを**そのまま再現**する(最初はタイル + パンくずで作ったが「バーそのものが良い」と
  言われて作り直した)。ブックマーク バー(id `"1"`)の直下を横に並べ、ほかの最上位フォルダ(その他のブックマーク等)は右端。
  - 表示はブラウザと同じくファビコン + サイト名だけ(タイトルが空ならファビコンだけ)。URL は `title` のツールチップ
  - フォルダ(`data-kind="folder-menu"`)は押すとドロップダウン(`.bm-menu`、`position: fixed`、`#menus` に入れる)。
    メニュー内のサブフォルダは**マウスを乗せると**右にサブメニュー、ブックマークに乗せると深いメニューを閉じる。
    メニューを開いている間はバーの別フォルダに乗せるだけで切り替わる(どれもブラウザの挙動に合わせた)
  - ブラウザと違い、メニューのブックマークを押しても**メニューは閉じない**(続けて選べるように)
  - メニューの末尾に「このフォルダをすべて選択 (n)」(`data-kind="select-all"`、子孫が対象。全部選択済みなら「解除」)
  - 中に選択を含むフォルダは `.has-selected`(青い枠とアイコン)
  - **縦は常にバーより下に出す**(ブラウザと同じ)。最初のメニューはボタンではなくバー(`.bmbar`)の下端から出し、
    `max-height` を画面下端までにして中をスクロールさせる。サブメニューは下に収まらなければ持ち上げるが、最初のメニューの
    上端より上には出さない。以前は画面に収めるため上にずらしていて、バーに重なってほかのフォルダが押せなくなっていた
  - 閉じるのはメニュー外の mousedown / Esc / スクロール / リサイズ(fixed なのでスクロールで位置がずれるため)
  - 本物は入りきらない分を「»」にしまうが、ここは全部見えるよう `flex-wrap` で折り返す
  - バーに検索欄はないので、バー表示では絞り込み欄を隠す
  - 編集画面(`#editor`)はバーのため**ブラウザの横幅いっぱい**(`max-width: none`)。名前の欄は見出し「新しいセット」の右に並べる
- **選択中のブックマーク**(`#selectedSection`): ブックマーク欄の下に、保存するとセットに入る項目を開く順で並べる
  (ファビコン・タイトル・URL・× で外す。ブックマークにない項目には印)。`updateEditorFooter()` のたびに描き直す。
  件数だけでは何を選んだか分からないという要望で足した。ブックマーク欄の**上**に置くと、選ぶたびにバーが下へずれて
  開いているメニュー(fixed)と食い違うので下に置き、フッターの「n 件を選択中」から `scrollIntoView` で飛べるようにした
- 行・メニュー項目の中身は ファビコン → タイトル(→ ツリーではホスト名)。ファビコンは `favicon` 権限で
  `chrome.runtime.getURL("/_favicon/?pageUrl=<URL>&size=32")` を 16px で表示する(ブックマークバーと同じブラウザのキャッシュ。
  外部へは取りに行かない)。一度も開いていないサイトは既定の地球儀アイコンになる。Brave でも動く
- 「ブックマークにないもの」の行も同じボタン(`data-kind="missing"`、`data-id` は配列の添字)

### ショートカットキー

- コマンド名は `01_open_slot` 〜 `03_open_slot`。`chrome://extensions/shortcuts` は manifest のキー名順で並ぶので
  数字を頭に付けている。`parseInt(command)` でスロット番号も取れる。`suggested_key` は付けない
- 失敗(未割り当て・削除済み・空)は画面に出ないので、アイコンに赤い「!」バッジを4秒出し、理由を `setTitle` に入れる
- セットを削除すると、それを割り当てていたスロットは空にする。フォルダの削除は検知していない(設定画面に「見つかりません」と出る)

### 設定画面のボタン

セット一覧の編集・削除は simple_memo と同じ形のアイコンボタン(26px・枠付き・ホバーで塗りつぶし、lucide 系の
鉛筆付きの四角とゴミ箱)。色はこの拡張の `--accent`(編集)と `--error`(削除)。

### 確認は二度押し

20 個以上を開くとき(ポップアップ)と、セットの削除(設定画面)は、1回目で表示を変え 3 秒以内のもう一度で実行する。
削除はアイコンだけだと確認中か分かりにくいので、1回目で赤く塗って「もう一度で削除」の文言を足す。
`confirm()` はポップアップを固めるうえ自動テストもしにくいので使わない。ショートカットキーからは確認なしで開く。

## テスト手順(Playwright + Brave Nightly)

使い捨てのスクリプトは scratchpad に置く(このリポジトリには置かない)。

1. リポジトリを `--load-extension` で読み込み、`ctx.serviceWorkers()` の URL から拡張の ID を取る
2. service worker で `chrome.bookmarks.create` を使ってテスト用のブックマークを作る(ブックマーク バーは `"1"`、
   その他のブックマークは `"2"`)。URL はテスト内で立てた `http://localhost:<port>/...`。名前は架空のもの
3. `popup.html` / `options.html` を普通のタブで開いて操作する。ポップアップの行は `data-id="<セットの id>"` で特定できる
   - **行を押すと `window.close()` でそのタブ自体が閉じる。** その後の待ちに `page.waitForTimeout` を使うと
     「Target page has been closed」で落ちるので、service worker 側の `setTimeout` で待つ
   - 開いたタブの URL は `ctx.pages()` で数える。`tabs` 権限がないので service worker の `tabs.query` では `url` が取れない
   - 選択中のタブの判定に `document.visibilityState` は使えない(Playwright 下では全タブ visible)。
     拡張ページから `tabs.query({ active: true, lastFocusedWindow: true })` の ID と `tabs.getCurrent()` の ID を比べる
     (ID は `tabs` 権限なしでも取れる)。ポップアップは自分のタブを閉じた拍子に別のタブが選択されるので、
     バックグラウンドの確認は設定画面から `sendMessage({ type: "open", ... })` を送って行う
   - **ショートカットキーはコードから設定できない**(`chrome.commands.update` は Firefox のみ)。ポップアップのキー表示は
     `page.addInitScript` で `chrome.commands.getAll` を差し替えてから `popup.html` を開いて確かめる
   - ファビコンの確認は、テストサーバーの一部のページに `<link rel="icon">`(赤い丸の data URL)を付けて一度開いてキャッシュさせ、
     編集画面の `<img>` を canvas に描いて中央の画素が赤いか(付けていないページは赤くないか)で見る
   - 編集画面の要素は `#picker button[data-kind=bookmark|folder][data-id=...]`、バーは `.bmbar .bm-chip`、メニューは
     `#menus .bm-menu:nth-child(階層) .menu-item` で特定する。サブメニューは `hover()` で開く。タイトルで引くときは
     `:has(.title:text-is("..."))`(`:has-text()` だとフォルダのタリーの数字と連結した文字列にも当たる)。選択状態は
     `.selected` / `.partial` クラスで見る
   - エクスポートは `page.waitForEvent('download')`、インポートは `setInputFiles('#importFile', path)`
4. 2026-10-25 に通した確認項目(88項目): セットがないときの案内・ポップアップにフォルダと検索欄を出さない・歯車で設定画面・キー未設定ならキー表示なし・設定済みなら実際のキーを表示 /
   セット作成(チェックボックスなし・クリックで選択と .selected 表示・絞り込みをまたいだ選択・ファビコンの位置と読み込み・キャッシュ済みサイトは実物・フォルダ行で子孫の一括選択/解除・点線の一部選択・絞り込み中のフォルダ行・木の順で保存・対応表の記録) / ブックマークバー(タブ切り替えと記憶・検索欄なし・全幅・バーの並びと右端のその他・ファビコンとサイト名だけで URL はツールチップ・チップで選択・選択を含むフォルダの印・メニューで中身・メニューで選択しても開いたまま・ホバーでサブメニューが右に・ブックマークに乗せると閉じる・すべて選択/解除・ホバーでバーのフォルダ切り替え・Esc と外側クリックで閉じる・低い画面でもメニューはバーより下で中をスクロール) / 選択中の一覧(開く順・ファビコン/タイトル/URL/外すボタン・件数・× で外すとメニューにも反映) / 名前の欄が見出しの右 / ブックマークの URL・タイトル編集への追従と
   古い対応の掃除 / 削除後も保存 URL で開く・「ブックマークにない」表示 / 同じ URL で登録し直すと再び結び付く /
   エクスポートに ID が入らない / 対応表を消してインポート → URL で照合 / 読み直しで重複しない /
   ブックマークレットを捨てる / 形式違いはエラー / 「ブックマークにないもの」を外して保存 / 並べ替え / 削除アイコンの1回目で確認の文言 / 削除でスロットも空に / 25件のセットの二度押し / バックグラウンドの既定オフ・一覧のチェックで即保存・編集しても残る・今のタブのまま開く・エクスポート/インポートで保持
5. **ショートカットキー(`commands.onCommand`)は自動テストできない**ので、キーを割り当てて手で確認する
   (成功時の動作と、割り当て先を消したときの「!」バッジ)
